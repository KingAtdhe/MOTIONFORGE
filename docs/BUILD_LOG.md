### 2026-11-18 / Phase 0 — Feasibility and project foundation
- **Implemented:**
  - Kotlin + Jetpack Compose single-module app (`eu.motionforge.app`) with clean package boundaries
    (`core/model`, `core/design`, `core/camera`, `core/pose`, `core/render3d`, `data`, `feature/*`).
  - Gradle 8.14.3 wrapper and version catalog; Dependabot config.
  - Navigation skeleton: bottom bar Home / Train / Progress / Profile. No fake controls — screens
    that belong to later phases say so plainly.
  - Train tab reads the bundled `exercises.json` through a strict parser (loading / error / empty states).
  - **Spike 1 – CameraX:** permission rationale → request → denied state (retry + open settings);
    Preview + ImageAnalysis bound to lifecycle, KEEP_ONLY_LATEST, single-thread executor,
    ImageProxy closed in `finally`, front/rear switch.
  - **Spike 2 – MediaPipe Pose Landmarker:** LIVE_STREAM, 15 fps cap, rotation handled, mirroring
    kept as metadata; MediaPipe types confined to `MediaPipePoseEngine`; landmark overlay toggle;
    tracking-state chip driven by `TrackingStateEvaluator` (TRACKING only after 5 consecutive good
    frames); inference time and results/s shown.
  - **Spike 3 – GLB:** Filament gltfio `ModelViewer` in Compose; named-clip selection, play/pause,
    replay, 1× / 0.5× / 0.25×, orbit drag; text fallback if Filament or the asset fails.
  - Test asset `spike_stick_figure.glb` generated by `tools/generate_spike_glb.py`
    (clips `idle_neutral`, `squat_down`, `squat_up`). Validated with Khronos glTF-Validator:
    0 errors, 0 warnings. **Not** the trainer avatar and **not** coach-reviewed content.
  - GitHub Actions CI: unit tests → debug APK → APK content check → lint report → APK artifact +
    rolling `debug-latest` pre-release on `main`.
- **Files changed:** whole project scaffold (see repository tree); `docs/DEPENDENCY_DECISIONS.md` added.
- **Build command and result:**
  - Full Android build **not run in the Phase 0 workspace** (no Android SDK; Google Maven and Maven
    Central unreachable). CI command: `./gradlew -Pmotionforge.requirePoseModel=true testDebugUnitTest assembleDebug`.
  - Pure-Kotlin sources (model, catalogue parser, pose geometry, tracking evaluator, frame limiter)
    compiled with Kotlin 2.0.21 and `-Werror`: **success**.
- **Tests run and result:** 27 JVM unit tests (synthetic landmark fixtures + bundled catalogue),
  run with JUnit 4.13.2 outside Gradle: **27/27 passed**. Same tests run in CI via `testDebugUnitTest`.
- **CI result (GitHub Actions, run 44284030901, commit 229e57f):** first run failed in the Gradle
  script (`java.net` resolved to Gradle's `java` extension; fixed with an import). Second run:
  unit tests ✅, `assembleDebug` ✅, APK content check ✅ (pose model 5.8 MB stored uncompressed,
  test GLB, catalogue), `lintDebug` ✅. Debug APK ≈57 MB, published as release `debug-latest`.
  All Android code (CameraX, MediaPipe, Filament, Compose) now compiles.
- **Device/emulator tested:** none yet. Requires a real Android phone (camera + GPU).
- **Known issues / unverified:**
  - Android-dependent code (CameraX, MediaPipe, Filament, Compose UI) has not been compiled yet —
    first CI run is the compile check.
  - Pose-model download URL and MediaPipe 0.10.26 resolution verified only by CI.
  - Overlay alignment assumes 4:3 preview and analysis; verify on device.
  - GLB is loaded synchronously on the main thread (small file). Move to async loading in Phase 2.
  - Portrait lock; landscape/tablet behaviour not designed yet.
- **Decisions made:** see `docs/DEPENDENCY_DECISIONS.md` (pinned stable versions, Filament gltfio over
  SceneView for now, model downloaded at build time, JSON tree parsing without a compiler plugin).
- **Device verification steps (Phase 0 acceptance):**
  1. Install `motionforge-debug.apk` from the `debug-latest` release; open the app.
  2. Home → Technical checks → Camera & pose. Read the rationale, tap Allow camera.
  3. Stand 2–3 m from the phone, full body visible: chip should go "Hold position" → "Tracking";
     skeleton overlay follows you; note inference ms and results/s.
  4. Step half out of frame → "Adjust camera". Cover the lens → "Move into view" / low confidence.
  5. Switch to the rear camera; press Home and return — camera must stop and restart cleanly.
  6. Deny permission on a fresh install → denied screen with retry and settings.
  7. Technical checks → 3D animation: three clips listed; play/pause, replay, 0.5×/0.25× work; drag orbits.
  8. Report phone model, Android version, inference ms and any crash.
